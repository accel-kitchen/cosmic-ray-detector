A. 本番ファーム（v2/COSMICRAY_DETECTOR_ESP32-S3-Nano-v2.ino）

高工数小A-1. AUTO_PWM の移植（コンパレータしきい値の自動較正）

プローブで実証済みの方式（duty を掃引し、ノイズ山を検出してその上側のニーを採用）を本番に移植する。起動時と AUTO_PWM コマンドで実行。

根拠: コンパレータはノイズと信号の分離窓が狭く（duty 16 で 10万/s 発振 → 24 で静粛）、固定値は基板個体差・温度で破綻する。DIGITAL / DUAL トリガモードを実用にする前提条件。プローブの autoPwm() がそのまま流用できる。

高工数小A-2. applyThresholdPwm() の *2 換算見直し

現状 pwmDuty = SIGNAL_THRESHOLD * PWM_MAX * 2 / ADC_MAX。*2 の根拠が不明で、SIGNAL_THRESHOLD > 2047 で duty が飽和する。回路の分圧比（PWM 平滑電圧 → コンパレータ基準）を実測し、正しい換算式に置き換えるか、A-1 の自動較正へ一本化して換算自体を廃止する。

根拠: プローブ側のコメントでも既知の疑問点。実測では duty 40 ≒ ADC 90 相当のしきい値で、現行換算（duty 40 → ADC 320 相当）と大きく食い違う。

中工数中A-3. デッドタイム削減（読み出しシーケンス最適化)

イベント毎の処理: COIN_SYNC_DELAY_US(50µs) → digital 3ch 読み → 5µs → analogRead(約47µs) → EXT 3ch 読み → リセット。改善候補:

・整定は実測 12–24µs なので、単独運用（EXT 無し）時は 50µs 待ちを短縮可能
・extEnabled でも実際に接続の無いチャンネルはスキップ（設定で ch 個別有効化）
・analogRead(47µs) を oneshot ではなく校正済み生読みへ（adc_oneshot_read 直叩きで短縮余地）

根拠: デッドタイム実測 ~100–110µs/イベント。リセット復帰は ≤24µs と速く、律速は読み出しシーケンス側。線源測定（数十/s〜）でデッドタイム比が効いてくる。

中工数小A-4. SET_OLED_ROT の本番移植

プローブに実装済みの SET_OLED_ROT:<0-3>（実行時回転変更）を本番にも追加し、Preferences に保存する。

根拠: 今回、本番は定数修正（setRotation 1→2）で対応したが、ケースの組み方・設置向きで再フラッシュが必要になるのは不便。

中工数小A-5. 音の追加改善

・音階量子化: 対数マップの出力を半音階（またはペンタトニック）にスナップ。隣接エネルギーの音が濁らず「音が変わった＝エネルギー帯が変わった」が明確になる
・同時計数音: DUAL/DIGITAL で外部一致したイベントだけ二音（和音/上昇音）にして耳で区別
・高レート間引き: レートが閾値（例 30/s）を超えたら n 発に 1 回だけ鳴らす。tone() キュー詰まり（~1000/beepMs [ev/s]）対策

根拠: 対数マップ（実装済み）で聞き分けは改善したが、連続音だと相対比較が難しい。音階化は教育用途（アウトリーチ）で特に効果的。

低工数小A-6. 設定一括ダンプ（GET_CFG 拡張）

thresh / duty / mode / sd / ext / oled / buzzer / beep(fmin,fmax,ms) / ble_name / auto_margin を 1 コマンドで JSON 風に返す。ダッシュボード接続時の初期同期が 1 往復で済む。

低工数中A-7. 波高のドループ逆補正

トリガ→ADC 読みまでの遅延 Δt が既知なので、実測したドループ曲線（指数減衰）で adc_corr = adc · exp(Δt/τ) と逆補正する。τ はプローブのドループ測定（SET_FS:8333 + SET_HOLDRESET:15000）から求める。

根拠: 1.5ms で 4095→180 まで垂れる実測から、55–60µs 遅延でも数 % の系統的過小評価がある。エネルギー較正の精度を上げるなら補正価値あり。

B. 波形プローブ（v2/COSMICRAY_WAVEFORM_ESP32-S3-Nano-v2.ino）

高工数中B-1. ADC クロックドリフト補正

実測でサンプル列が micros() 基準に対し約 4ppm（0.335 サンプル/秒）ドリフトし、COMP トリガの位置決めが約 5 分で 100 サンプルずれる。対策候補:

・起動時に数十秒かけて実効 fs を較正し、indexFromUs() の換算に反映
・または一定周期（例 30 秒）で DMA を自動再アンカー（現在は START/overflow 時のみ）

根拠: 現在の settle 統計は長時間運用で単調増加する偽値になる（実測 23µs → 547µs）。ドリフト補正が入れば settle_mean が常に信頼できる。

中工数小B-2. MEASURE_SETTLE コマンド

「STOP → DMA 再アンカー → 数秒だけ COMP 収集 → settle の中央値を報告」を 1 コマンド化。ドリフトの影響を受けない直後データだけで整定時間を返す。

根拠: 現在は「START 直後の値だけ読む」という手動運用でカバーしているが、コマンド化すれば誰でも正しい値が取れる。B-1 実装までの実用的な代替でもある。

中工数小B-3. COUNT_RATE テスト（digital 計数のデッドタイム実測）

一定時間コンパレータ端エッジだけを ISR で計数し、レート vs 取りこぼしの関係から digital 計数の実効デッドタイム（期待値: 数 µs）を実測する。

根拠: アナログ読みのデッドタイム ~100µs に対し、波高不要ならコンパレータ計数で桁違いに速くなるはず。定量値があれば本番の DIGITAL モードの仕様が書ける。

低工数小B-4. AUTO_PWM 掃引の二分探索化

現在は 0→255 を step 8 の線形掃引で約 6 秒。ノイズ山より上側は単調に静かになるので、山の検出後は二分探索でニーを絞れば 1–2 秒になる。

C. ダッシュボード（v2/index.html）

高工数小C-1. ビープ設定 UI（SET_BEEP / GET_BEEP / BEEP_TEST）

ファーム側は実装済み（対数マップ・Preferences 保存）だが UI が無い。サイドバーの Buzzer トグルの下に、fmin/fmax スライダー（対数目盛）＋鳴動時間＋「テスト音」ボタンを追加し、SET_BEEP:<min>,<max>,<ms> / BEEP_TEST を送る。接続時に GET_BEEP で現在値を同期。

根拠: 音の好みは耳で追い込むものなので、シリアルコンソールより UI スライダーが圧倒的に速い。

中工数小C-2. PWM duty 直接制御 + AUTO_PWM ボタン

現在 DUTY は THRESH: 応答のパース表示のみ（読み取り専用）。A-1 のファーム移植と合わせ、duty の数値設定と「自動較正」ボタン（掃引ログの表示付き）を追加する。

根拠: DIGITAL/DUAL モードを UI から使えるようにするにはコンパレータしきい値の制御が不可欠。

中工数小C-3. OLED 回転 UI

A-4（SET_OLED_ROT 本番移植）後、OLED トグルの隣に 0/90/180/270° の回転セレクタを追加。

中工数中C-4. keV 較正の読み込み（ライブヒストグラムのエネルギー軸化）

plotter.html の Energy Cal がエクスポートする較正 JSON（E = a·ADC + b）をダッシュボードに読み込み、Analysis タブのヒストグラム横軸を ADC / keV で切替できるようにする。localStorage キーを共通化すれば同一ブラウザなら自動連携も可能。

根拠: 較正済みの検出器なら「いまのイベントは ~600 keV」とライブで見えるのは教育・デモで強い。プロッタ側に較正資産（Th-232 系列プリセット・JSON 入出力）が既にある。

D. プロッタ（plotter.html）

高工数中D-1. Energy Cal 強化

現状: 手動ピーク指定（クリック）＋線形 2 点フィット（E = a·ADC + b、R² 表示）。強化案:

・ガウスピークフィット: クリック位置の近傍でガウス＋直線背景をフィットし、ピーク中心を bin 分解能以下で決定。FWHM からエネルギー分解能も算出・表示
・自動ピーク検出: スペクトルの平滑化＋極大探索で候補ピークをマーカー表示（クリックの補助）
・2次多項式フィット: 状態オブジェクトに model:'linear' フィールドが既にあり拡張前提の設計。ADC 高域の非線形（ドループ・アンプ飽和）を吸収
・フィット誤差: a, b の標準誤差と較正の 1σ バンド表示
・プリセット追加: 現在 Th-232 系列のみ → Cs-137 (661.7)、Co-60 (1173.2/1332.5)、K-40 (1460.8) などのプリセット切替

根拠: 較正精度は現状「クリックした bin の中心」が限界。ガウスフィットで一桁改善し、FWHM はシンチ＋SiPM の性能評価にそのまま使える。

低工数小D-2. wave_plotter.html との役割整理

plotter.html（イベントログ解析）と wave_plotter.html（波形プローブ用）の使い分けを両ページのヘッダに一言明記し、相互リンクを張る。

中工数小E-2. 実測知見の技術ノート化

本ページ冒頭の「実測で分かったこと」（整定 12–24µs、リセット復帰 ≤24µs、デッドタイム ~100µs、COMP/LEVEL の等価性、コンパレータのノイズ山と duty 設定指針、ドループ特性）を MANUAL.html の技術資料節として整理する。測定条件（プローブ設定・日付・基板）も併記。

根拠: 測定値の出典が会話ログにしか無い状態は再現性が低い。次の基板ロットや後継機の設計判断の基礎データになる。

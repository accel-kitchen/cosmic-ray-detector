当初の問い —「トリガがかかってからどれぐらい待てばピークを採れるか」— の答えは 「待ってはいけない。しきい値を超えた最初の1点がすでにピークである」。

V1 基板のパルスは 立ち上がり 0.7 µs / 減衰 τ≈199 µs の非対称波形だった。 立ち上がりは ESP32-S3 のどのサンプリング手段でも分解できない（DMA 連続モードの上限 12 µs でも足りない）。 一方で減衰は 199 µs と十分に遅いため、しきい値超えを検出した時点のサンプルは まだピークの数％以内に留まっている。そこから待つと単調に損をするだけである。

したがって現行ファームの SAMPLE_PEAK が正しく動いているのは int peak = trig; の 1 行のおかげであり、トリガ後に撃つ追加の analogRead は 実測で 94〜98% のイベントにおいて一度も勝っていない。

ただし別の問題が見つかった。 アンプ出力の DC 点が ADC=5（約4 mV）と ESP32 の ADC レンジ最下端に貼り付いており、ベースラインノイズの 18.7% が 0 でクリップされている。 この領域は ADC が非線形なため、低エネルギー側のイベントは「トリガはできるが波高値が正しく測れない」状態にある。 詳細は「低エネルギー成分が正確に測れない理由」を参照。

2 つの取得モードは全く別経路（DMA は SAR の DMA 転送、POLL は oneshot API）にもかかわらず、 同じ τ を返した。パルス形状の測定として信用してよい。

素直にフィットすると区間によって 177〜190 µs とばらつくが、これは後述の ADC 下端の問題によるもの。 ADC の信頼できる領域だけを使うと τ ≈ 199 µs に収束する。

立ち上がり時間 導出

0.7 µs はどちらのサンプラでも直接は分解できない。しかし間接的に測れる。

しきい値を超えた最初のサンプルは、交差時刻から U(0, T) に一様に落ちる（T はサンプル間隔）。 それがピークより手前に落ちる確率は Δ/T である（Δ = しきい値通過からピークまでの時間）。 「ピークがトリガ点ではなかったイベントの割合」を数えれば Δ が求まる。

モードTピーク≠トリガ点Δ = 割合 × T
DMA12.00 µs5.7%0.68 µs
POLL32.30 µs2.5%0.80 µs
サンプリング周期が 2.7 倍違う 2 つの測定が同じ値を出した。この 0.7〜0.8 µs は信用できる。

飽和はしていない 実測

ADC 生値が 4090 以上に達したイベントは DMA 4938 中 3 件（0.1%）、POLL 2180 中 2 件。 アンプの飽和もクリップも実質起きていない。

2. サンプリングによる波高の取りこぼし

ピークはトリガ点にあるが、トリガ点そのものが真のピークより少し遅い。 パルスの立ち上がり（0.7 µs）はサンプル間隔より遥かに速いので、 最初のサンプルはすでに減衰カーブ上のどこかに落ちている。

その遅れ δ は U(0, T) に一様なので、 採れる割合は x = exp(−δ/τ) の分布として計算できる（τ=199 µs）。

サンプル間隔平均ばらつき (sd)備考
12.0 µs（DMA）97.0%± 1.9%
32.3 µs（POLL＝実機）92.3%± 4.2%現行ファームはここ
60 µs85.9%± 7.7%
この ±4.2% は「サンプリングだけで乗る広がり」で、検出器本来のエネルギー分解能に二乗和で足される。 仮に本来の分解能を σ=6.4%（FWHM 15%）とすると、 POLL では √(6.4²+4.2²)=7.7% → FWHM 18.0%、 DMA なら √(6.4²+1.9²)=6.7% → FWHM 15.7%。無視できる大きさではない。

ピークがトリガ点だったイベントの割合 実測

DMA 94.3%（4659/4938）、POLL 97.5%（2126/2180）。

POLL のほうが高いのは、サンプルが粗いほど「立ち上がりの途中を踏む」確率が下がるため。 いずれにせよトリガ後の追加サンプルは 94〜98% のイベントで無駄ということになる。

3. 低エネルギー成分が正確に測れない理由

先に結論。 AUTO_THRESH のアルゴリズム自体は壊れていない。 「ノイズの最大値＋マージン」という置き方は正しく、トリガも正常に動いている。 問題は、そうやって決まった正しい位置（ADC 77）が、たまたま ADC が正しく測れない領域の中にあること。 根本原因はアンプ出力の DC 点であって、AUTO_THRESH はその犠牲者である。 （前の説明で「AUTO_THRESH が壊れたノイズ分布を見ている」と書いたのは不正確だった。訂正する。）

3.1 何が起きているか

ESP32 の ADC は減衰 11/12 dB でも 入力 100 mV 前後（≒130 カウント）以下では非線形で、 下端では 0 に潰れる。V1 基板のアンプ出力は静止時に約 4 mV しかなく、 信号がまるごとこの使えない領域の底に置かれている。

3.2 因果の流れ

① アンプ出力の DC 点が約 4 mV（ADC=5）
↓
② ノイズは ADC=0〜7 に収まる。下側は 0 でクリップ、実測の max は 17
↓
③ AUTO_THRESH が max + margin = 17 + 60 = 77 にしきい値を置く
— ここまでは設計どおりで、何も間違っていない
↓
④ トリガは正常に働く。 しきい値もノイズも同じ ADC カウント空間で比較しているので、 圧縮の影響は打ち消し合う。イベントを取りこぼしてはいない
↓
⑤ しかし波高値は正しくない。 ADC 77 前後は非線形域のど真ん中。 ここでトリガした低エネルギーイベントは、トリガはできるが波高が圧縮されて記録される

つまり 「低エネルギー成分が見えない」のではなく「見えているが値が間違っている」。 これがこの問題の厄介なところで、イベント数を増やしても改善しない。

3.3 実測での現れ方 実測

電子回路が線形なら、パルスの形は振幅に依らないはずである。 ところがイベントをピーク振幅の四分位に分けて τ を測ると、振幅で 25 µs もばらつく。

小振幅パルスは波形の大半が ADC 100 以下を通るため、この誤差をまともに受ける。 大振幅パルスは尾の後半でしか影響を受けない。それが図2の赤い傾きの正体である。

3.4 誤差の内訳 部分的にしか分離できない

この歪みには 2 つの成分が混ざっており、今回のデータでは完全には分離できなかった。 正直に両方を挙げる。

  1. ベースラインの過大減算。 測定したベースライン（ADC=5）はクリップされた分布の平均なので、 真のゼロ点より高い。これを差し引くと全振幅が下振れし、小振幅ほど相対的に大きく効く。
    検証: 減衰を A·exp(−t/τ) + c と 3 パラメータでフィットすると c は常に負（−0.010〜−0.029）で、τ は 182/195/201/201 µs とかなり揃う。 ただし c をカウントに直すと −2.1/−5.8/−9.7/−8.6 とばらつき、単一の固定オフセットでは説明しきれない。
  2. ADC 自体の圧縮・コード抜け。 図1 の ADC=1,2 の落ち込みが示すとおり、 下端では 1 カウントの重みが一定でない。こちらは補正のしようがない。

実務的には、原因の内訳を突き止めるより「ADC 100 以下の値は使わない」で運用するほうが確実である （図2 の青がそれ）。

3.5 副作用: 自己診断が効かない

calibrateThreshold() は min/max/mean/sd を出力し、 スケッチのコメントでは「マージンが sd の 5 倍程度あるか」で妥当性を判断するよう書いてある。 しかし分布の下半分がクリップされているため sd は過小評価され、mean は上振れする。 この自己診断は現状あてにならない。

4. 対処の方向

4.1 ハードウェア（本質的な対処）

アンプ出力に 150〜200 mV 程度の DC オフセットを載せ、ベースラインを ADC 200〜300 付近まで持ち上げる。 そうすればしきい値も信号も ADC の線形領域に入る。

既知の未対策事項として A0 に最大 5V が入りうる問題がある（LT1807 の出力が分圧なしで A0 直結）。 ここに分圧を入れると信号が小さくなり この DC 点の問題は悪化する。 分圧とオフセットは必ず一緒に設計すること。

付録: 再現手順

  1. v1/COSMICRAY_WAVEFORM_ESP32-S3-Nano を書き込む（ESP32S3 Dev Module + USB CDC On Boot=Enabled）
  2. arduino/wave_plotter.html を開いて USB 接続
  3. BENCH → analogRead の実所要時間を得る
  4. AUTO_THRESH → GET_CFG（ヘッダを記録に残すため）→ START
  5. 宇宙線の約 1 Hz では統計が溜まらない。線源を近づけるか、しきい値を下げて SiPM のダークカウントを拾う。 回路が線形なら 1 p.e. のダークパルスも muon のパルスも形は同じなので、波形測定にはそれで足りる
  6. 数千イベント収集したら SET_MODE:POLL で同じ測定を行い、両者を比較する

# v2 コンソール — 機能の対応表と確認状況

`v2/index.html` の全機能が `v2/console/` のどこに移ったかと、その確認方法の一覧。
通信・行の解析・保存形式・サーバー送信のコードは `assets/js/core.js` に中身を変えずに移してある
（画面に触れていた箇所だけを `settings` / `Bus` / `Hooks` に置き換えた）。

確認の記号:

- **デモ** — デモモードで操作して確認済み（2026-10-07、Chrome、1366×650・1024・768・400 px）
- **比較** — 旧ページと同じ入力を与え、出力がバイト単位で一致することを確認済み
- **実機** — 実機またはネイティブのダイアログが必要。下の「実機で確認すること」に回した

## v2.1 基板（2026-11-15 追加）

OHASHI・OKOME と同じページ・同じ `core.js` を、機種プロファイル `v21`（`MODEL_PROFILES.v21`、`localStorage.detectorModel` = `v21`）で使う。
相手のファームは v2.1 プロジェクトの `arduino/COSMICRAY_DETECTOR_ESP32-S3-Nano-v2.1`（FW 2.1.0、ログ形式 FMT:3。プロトコルは同じフォルダの `description.md`）。
プロファイルの旗: `fmt3`（v2.1 の応答と保存の列）、`scopeTrig: false`（撮り方・再アームが無い）、`scopePausesCount: false`（オシロ中も計数が続く）。

確認の記号に **再生** を足す: 2026-11-15 に 1 枚目の実機から取った出力（初回起動の CALIBRATE、1650 イベント、全 GET の応答、WF 行 12 本）を、模擬の Web Serial のポートから流して確かめた。
Web Serial そのもの（ポートの選択・開く・DTR/RTS）は通っていない。

書き込みページ（`flash.html`）は v2 / v2.1 / OKOME / v1 のタブを持つ（2026-11-21）。v2.1 は ESP Web Tools（`firmware/cosmicray-v21.bin`、手順は v2 と同じ）、OKOME は nRF52840 なので UF2 のダウンロードと XIAO-BOOT ドライブへのコピーの案内（ブラウザからの直接の書き込みは無し）。ヘッダーの「書き込み」は全機種に出て、機種のタブ（`#v2` `#v21` `#okome`）で開く。v2 のファームを v2.1 基板に書くと動かない（逆も同じ）ので、ページに警告を出している。
マニュアル（`manual.html`）に v2.1 の章はまだ無い。

新しいアプリだけを 0x10000 に書いた（NVS はそのまま。書いたあとハッシュ一致）。pyserial で直接と、コンソールの画面からブリッジ
（Web Serial の代わりに WebSocket で COM62 につなぐ。setSignals もそのまま基板の線に通す）で確かめた:
`GET_VER` → `VER:FW=2.0.0 BOARD=v2 BUILD=2026-11-20`、`SET_TIME` → `### TIME …` と `TIME:… SRC:PC`（基板の時計は PC と同じ秒）、
`RESET` → `RESET:OK` のあとに新しい起点の TIME 行、`GET_TIME`（設定前は `TIME:0 SRC:NONE`）。コンソールでは 接続先 に版と時計、
更新の知らせは出ない（manifest と同じ版）、TIME 行が記録に入る、予約 12 秒で一時停止と MARK 2 行、「データを消去」で RESET と
新しい TIME 行、診断レポート、SD の欄は「no card」と表示、`Unknown command` 0 件。切断（RTS → DTR の順に下げる）のあとも
基板は数え続け、PC の時刻も保っていた。**確かめていない**: 2 台の同時計数、PC の音（耳で聞いていない）、本物の Web Serial のポート選択（ブリッジを使った）、Bluetooth。

## 実機で確認すること

1. **USB 接続**: 「USBでつなぐ」→ ポート選択 → ヘッダが「接続中 · USB」、検出器の名前が出る。グラフが動く。
2. **ESP32 がダウンロードモードで止まったとき**（`ESP-ROM:` が受信ログに出る）に自動で通常起動するか。
3. **ポートが使用中**（Arduino IDE のシリアルモニタを開いたまま）でメッセージ帯にエラーが出て、閉じられるか。
4. **Bluetooth 接続**: 名前欄を変えて接続できるか。電源を切る／遠ざけると、ヘッダがコーラルで点滅し「◯ 秒後に ◯ 回目の再接続」を数え、戻すと再接続して同じ自動保存ファイルに続けて書くか。
5. **自動保存**: 「保存フォルダを選ぶ」→ `<名前>_<日付>.dat` ができ、件数が増えるか。形式を「.dat と .csv」にして両方できるか。「保存先を先に選ぶ」から選んでからつないでも同じか。
6. **ダウンロード** .dat / .csv、**PNG 保存**（ヒストグラム・レート）、**.wfm 保存**（オシロ）が保存ダイアログ経由で書けるか。中身が旧ページと同じ形か。
7. **タブを閉じる**とき、未保存のイベントがあればブラウザの確認が出るか。
8. **基板の設定**を実機で一通り: しきい値の設定と自動校正、PWM と Auto PWM（約 8 秒）、トリガーモード 3 種、機能スイッチ 5 つ（OLED の表示・ブザー・振動が実際に変わるか）、ブザー／振動のテスト。
9. **名前を変えて再起動**: 基板が再起動し、新しい名前で表示されるか。次回の Bluetooth 接続で新しい名前が使われるか。
10. **オシロスコープ**: 確認ダイアログ → 画面がオシロの表示に切り替わり（計数の画面と同じ紙色の配色のまま）「計数停止中」が数える → 閉じると計数が戻り、閉じている間のぶんがデッドタイムに入っているか（統計 > 総デッドタイム）。Bluetooth 接続中は注意文が出るか。
11. **別の基板**につなぎ替えると、メッセージ帯に「別の検出器につながりました」が出るか（基板 2 枚）。
12. **サーバー送信**: ログイン → 送信開始 → 件数が増える → 停止 → ログアウト。http:// の URL で警告が出るか。
13. **Firefox / Safari** で開くと、USB と Bluetooth のカードが無効になり理由が出るか。
14. **1366×768 のノート PC** の Chrome（ブラウザ枠込み）で、計測画面の数値・グラフ 2 枚・下の 1 行がスクロールなしで見えるか。
15. **オシロスコープの再アームと連続撮影**（新しいファームを書き込んでから）: 受信ログの `### trigger above … , re-arm at or below …` が、画面の設定どおりか。しきい値 120 のまま（再アームは既定の「しきい値 − 5」= 115）で波形が出るか（以前は、A0 のベースライン約 86 がしきい値の半分 60 より上で、1 本も出なかった）。入力欄を 60 にすると（水準 60 がベースライン 86 のゆらぎの下限より下になり）出なくなり、5 に戻すと出るか。しきい値の線をドラッグすると、青緑の線が一緒に動き、離したあとも波形が出続けるか。「連続」に切り替えて、ベースラインの窓がレート上限の間隔で出続けるか。
16. **V1 のオシロスコープ**（`v1.html` と、更新した V1 の ESP32-S3 版・Arduino Nano 版）: 受信ログの `### trigger above … , re-arm at or below … (threshold - 5).` が、画面の設定どおりか。トリガーのまま波形が出るか、「連続」でベースラインの窓が出続けるか。Arduino Nano 版は、連続のあいだも約 0.5 秒に 1 本が上限（9600 bps）。入力欄を、しきい値に近い値（例: しきい値 30 で 28）にすると、水準がベースラインより下になって出なくなるか。 しきい値の線をドラッグ（または ↑↓ キー）して離すと、受信ログに `SET_THRESH:信号,リセット` が 1 回出て、基板が `THRESH:` で返し、線が戻らずに確定するか（Nano 版は応答に最大 0.5 秒かかる）。リセットは「信号 − もとの差」になっているか（設定ドロワーの欄で確認）。再アームの線が一緒に動くか。
17. **OKOME（MUON FOB、実機）**: ファーム `firmware/muon_fob` を書き込んだ基板で — 選ぶ画面で OKOME を選ぶ → USB 接続でヘッダが「OKOME · MUON FOB」、グラフが動く。受信ログに `Unknown command` が出ない（`GET_GPS` を送っていないこと）。Bluetooth は名前欄 `MuonFob` のまま（前方一致）で `MuonFob-XXXX` が見つかり、接続できるか。HV の 3 段を切り替えると受信ログに `### HV: … V` が返り、ボタンの選択が追従するか。HV を変えたあと「自動校正」でしきい値が落ち着くか。オシロは 6 µs・81 点で、パルスの形（ピークホールドではない生の出力）が出るか。LED・ブザー・振動のスイッチが効くか。保存ファイルの先頭に `# Detector model: OKOME` が入り、解析ページ（plotter）で読めるか。OHASHI を選び直したとき、Bluetooth 名が `CosmicRay` に戻るか。
18. **v2.1（実機）**: FW 2.1.0 を書き込んだ v2.1 基板で — 選ぶ画面で v2.1 を選ぶ → USB 接続（Chrome / Edge、ポートを選ぶ）で見出しが「v2.1」、グラフが動く。受信ログに `Unknown command` が出ない。詳細設定の VTH・ベースライン・HV に値が入る。「ノイズを測る」で結果が出る。「自動で合わせる」（AUTO_VTH）・「まとめて較正」（CALIBRATE）は DAC の EEPROM を書き換えるので、遮光した状態で、試すときだけ。オシロを開いても総イベント数が増え続け、波形の頂点がトリガーの約 48 µs 後に来るか。しきい値の線がベースラインの上に出て、ドラッグすると `THRESH:` が返るか。自動保存の .dat が 21 列で、解析ページ（plotter）で読めるか。Bluetooth（名前 `CosmicRay`）でも同じか。
19. **FW 2.0.0（2026-11-20）を書き込んだ v2 基板**（書き込みページから）: 起動の受信ログに `### Firmware: FW=2.0.0 BOARD=v2 BUILD=2026-11-20` が出るか。詳細設定 > 接続 に「ファームの版: 2.0.0 (2026-11-20)」「基板の時計: PC の時刻に合わせた」が出るか。`Unknown command` が出ないか（v2 のファームは知らないコマンドに黙る）。古いファームの基板では「版を答えない古いファーム」と、https で開いたときだけ更新の知らせが出るか。
20. **PC の時刻（SET_TIME）**: GPS なしの基板で、microSD のログ（`LOG000n.TXT`）に `### TIME <t_us> <UTC 秒> src=PC` が入るか。「データを消去して最初から」（RESET）のあとにもう 1 本入るか。そのログを解析ページで読むと「測定の日時」が PC の時計と数秒以内で合うか。GPS が時刻を持っている基板では TIME 行が出ず、「基板の時計: GPS」になるか。
21. **microSD の取り込み（USB）**: 詳細設定 > 検出器の機能 >「ファイルの一覧を読む」で、記録中のファイルに「記録中」が付くか。保存したファイルが、SD を抜いて PC で直接コピーしたものと（取り込み時点までは）バイト単位で一致するか。取り込みの最中も計数が続き、取り込みのあとも記録中のファイルに書き続けているか（追記で開き直している）。Bluetooth 接続ではボタンが押せず、理由が出るか。速さ（1 MB あたり何秒か）を記録する。
22. **同時計数（2 台）**: 2 台を COIN のケーブルでつないで重ねたとき、計測画面の「同時」が偶然の目安より桁で大きくなるか。横に離すと目安に近づくか。
23. **このパソコンで音を鳴らす**: 実機のイベントで PC から音が出て、基板のブザーと同じ高さの順になるか。基板のブザーを OFF にしても PC の音は出るか。

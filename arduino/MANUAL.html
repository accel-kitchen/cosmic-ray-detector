1. 装置の概要

本装置は SiPM (Silicon Photomultiplier) を用いた宇宙線検出器の v2 基板用ファームウェアです。 SiPM で受けたパルスをアンプ・ピークホールド回路で増幅し、外部コンパレータで閾値判定したものをマイコンが 記録します。さらに 外部 3 系統の検出器（デジタル + アナログ）を接続して同時計測、 コインシデンス判定、音声ジャックへの出力、ブザー鳴動に対応しています。

対応ボード Arduino Nano ESP32 (ESP32-S3)。ボード定義は Arduino IDE の「ボードマネージャ」から esp32 by Espressif Systems を入れると使えます。

2. v1 からの主な変更点

項目v1 (旧)v2 (新)
トリガー方式 ADC を polling し閾値比較 外部コンパレータ + 割り込み。閾値は D2 の PWM Duty で設定
ピークホールド 信号レベルが下がるまで待機 D8 から短いパルスを出して強制リセット
温度センサ NTC サーミスタ (A3, ADC) BME280 (I²C, U4)
コインシデンス Master/Slave 2 台構成 3 台の外部検出器を同時入力 (DIG_IN1-3)
出力インターフェース なし (LED のみ) ブザー、音声ジャック (COIN_OUT, ANA_OUT)
ログ Mode 欄 (Master/Slave) Dig1-3 / Ana1-3 欄を末尾に追加

3.2 信号の流れ (簡易図)

  SiPM → アンプ → ピークホールド ─┬─ A0 (ADC 読取)
                                    └─ 音声ジャック (ANA_OUT)

  ピークホールド ─ コンパレータ ─ D0 (割込入力: Trigger)
                      ↑
                      PWM Duty (D2) で閾値設定

  D8 (TriggerReset) ─ パルス → ピークホールドをクリア

  外部検出器1-3 ─ DIG_IN1-3 (D6/D5/D4) / ANA_IN1-3 (A1/A2/A6)

  コインシデンス成立 → D7 (COIN_OUT) パルス & D1 (ブザー) 鳴動 & A7 (振動モーター) 振動

4. 開発環境のセットアップ

4.1 必要なもの

  • Arduino IDE 2.x (または PlatformIO)
  • ESP32 Arduino Core (ボードマネージャから)
  • USB Type-C ケーブル (Nano ESP32 用)

4.2 必要ライブラリ

Arduino IDE の「ライブラリマネージャ」で以下を検索してインストールしてください。

BLE と Preferences は ESP32 Arduino Core に含まれるので追加インストール不要です。

4.3 ボード設定

  1. Arduino IDE → ツール → ボード → Arduino Nano ESP32 を選択
  2. USB CDC On Boot を Enabled に設定 (USB シリアルが使えるようになる)
  3. ポートは Nano ESP32 を USB 接続後、COMxx (Win) / /dev/cu.usbmodem... (Mac) を選択

5. ファームウェアの書き込み

  1. 本ディレクトリ内の COSMICRAY_DETECTOR_ESP32-S3-Nano-v2.ino を Arduino IDE で開く
  2. 左上の ✓ (検証) ボタンでコンパイル
  3. → (アップロード) ボタンで書き込み
  4. 書き込み完了後、シリアルモニタ (9600 baud) を開くと "Booting v2..." と表示される
初回書き込み時の注意 Nano ESP32 がブートローダモードにならない場合、ボード上の BOOT ボタンを押しながら RESET を一瞬押してください。その後 IDE からアップロードが可能になります。

6. 起動と基本操作

6.1 起動時のシーケンス

  1. 電源 ON → シリアルで "Booting v2..." 出力
  2. Preferences から閾値を読込 (初回は自動校正)
  3. BLE 広告開始: デバイス名 "CosmicRay"
  4. OLED にオープニング画面 (2 秒)
  5. BME280 を探索 (0x76 → 0x77)
  6. D0 に割込登録 → 計測開始

8. コマンドリファレンス

シリアル (9600 bps) または BLE RX 特性への書き込みでコマンドを送ります。改行 (LF または CR) で確定します。

8.1 閾値・トリガー設定

GET_THRESH

現在の閾値と PWM Duty を THRESH:<sig> DUTY:<duty> の形式で返します。

SET_THRESH:<signal>

ANALOG モードの信号閾値を 0-4095 の範囲で設定し、Preferences に保存します。例: SET_THRESH:1200。

v1 から仕様変更: カンマ区切りの 2 引数 (SET_THRESH:sig,rst) は廃止。 RESET_THRESHOLD はハードウェアコンパレータが担当するため不要です。
この閾値は ANALOG モードのソフト判定用です。DIGITAL / DUAL モードのコンパレータ閾値は SET_PWM / AUTO_PWM で独立に設定します (旧 ×2 換算式は廃止)。
AUTO_THRESH / AUTO_THRESH:<margin>

A0 (ANA_OUT) のノイズフロアを 100 サンプル測定し、最小値 + マージン を信号閾値として自動設定します。 ダーク環境で一度実行してください。

  • AUTO_THRESH … 現在のマージン (既定 40) で再校正します。
  • AUTO_THRESH:<margin> … マージンを指定値に設定してから再校正します (例 AUTO_THRESH:60)。設定値は Preferences に保存されます。
GET_AUTO_MARGIN / SET_AUTO_MARGIN:<n>

AUTO_THRESH がノイズフロアに上乗せするマージンを取得・設定します。応答は AUTO_MARGIN:<n> (既定 40)。Preferences に保存されます。

GET_MODE / SET_MODE:DIGITAL|DUAL|ANALOG

計測モードを取得・設定します。応答は MODE:ANALOG|DUAL|DIGITAL。

  • ANALOG (既定) … A0 のピークホールド値をソフトでポーリングして判定します。
  • DIGITAL / DUAL … 外部コンパレータ出力 (D0) の割込でトリガーします。

8.2 コンパレータ閾値 (PWM)

DIGITAL / DUAL モードでコンパレータ (D0) が使うトリガー閾値です。D2 の PWM Duty で生成します。ANALOG モードでは使用しません。

GET_PWM / SET_PWM:<0-255>

コンパレータ閾値の PWM Duty を取得・設定します。応答は PWM:<duty>。

AUTO_PWM / AUTO_PWM:<target_edges_per_s>

コンパレータ閾値 (D2 の PWM) を自動校正します。Duty を掃引してノイズの尾根 (ridge) のすぐ上の点を探し、 完了後に PWM:<duty> を出力します。任意で目標エッジレート (回/秒) を AUTO_PWM:<target_edges_per_s> のように指定できます。 DIGITAL / DUAL トリガーを使う前に一度実行してください。

コンパレータ閾値は SET_THRESH (SIGNAL_THRESHOLD) から独立しました (旧バージョンの誤った ×2 換算式は廃止)。ANALOG モードでは使用しません。

8.3 オシロスコープ / 波形ストリーミング

SET_SCOPE:ON|OFF / GET_SCOPE

波形ストリーミング (オシロスコープ) モードを ON/OFF します。応答は SCOPE:ON / SCOPE:OFF。

SCOPE が ON の間は計測 (カウント) は一時停止します。
SET_SCOPE_RATE:<n> / GET_SCOPE_RATE

波形ストリーミングのサンプルレートを取得・設定します。応答は SCOPE_RATE:<n>。

8.4 ブザー音

GET_BEEP / SET_BEEP:<min_hz>,<max_hz>,<ms>

検出時のビープ音を取得・設定します。応答は BEEP:<min>,<max>,<ms> (既定 500,4000,25)。

各イベントはパルス高 (エネルギー) を対数的にピッチへマッピングして鳴ります。 閾値付近 (低エネルギー) で min_hz、ADC 最大値 (高エネルギー) で max_hz になります。

制約: min ≥ 50、max > min、max ≤ 20000、ms は 1–500。

ビープはノンブロッキングで鳴るため、計測デッドタイムを増やしません。
BEEP_TEST

min / 中間 / max のテストトーンを順に鳴らし、設定を確認します。

8.5 振動モーター

配線: GPIO 直結は不可 振動モーターは A7 (GPIO14) で駆動します。基板上は未接続の空きピンなので後付け配線が必要です。 D13 は使えません — microSD の SCK と共用なので、モーターを繋ぐと SPI 波形が潰れて SD ログが壊れ、 逆に SD アクセスのたびにモーターが唸ります。
1027 コイン型 (10×2.7mm) の定格電流は概ね 75〜90mA、起動時はさらに大きく、 ESP32-S3 GPIO の絶対最大定格 40mA を超えます。直結せず、 A7 → 1kΩ → NPN (2N3904 / S8050) または N-ch MOSFET (2N7002) のベース/ゲート、 モーターと並列に還流ダイオード (1N4148)、端子間に 0.1µF を入れてください。 ブラシノイズと電流スパイクは SiPM 前段の誤トリガ源にもなります。
SET_VIB:ON|OFF / GET_VIB

検出時の振動を ON/OFF します。応答は VIB:ON / VIB:OFF。 Preferences に保存されるので次回起動時も維持されます (既定 ON)。 OFF にすると鳴動中でも即座に停止します。

GET_VIB_MS / SET_VIB_MS:<min_ms>,<max_ms>

振動の長さを取得・設定します。応答は VIBMS:<min>,<max> (既定 20,120)。

ブザーがピッチを変えるのと同じ考え方で、各イベントはパルス高 (エネルギー) を対数的に 振動時間へマッピングします。閾値付近 (低エネルギー) で min_ms、 ADC 最大値 (高エネルギー) で max_ms。大きい事象ほど長く「ぶるっ」と来ます。

制約: min ≥ 1、max > min、max ≤ 500。

振動の停止は loop() 側で行うノンブロッキング方式なので、 ビープと同様に計測デッドタイムを増やしません。
VIB_TEST

min / 中間 / max の長さで順に振動させ、設定を確認します。 BEEP_TEST と違い待ち時間の間ブロックしますが、 その分はデッドタイムに計上されるので計数率は狂いません。

8.6 機能 ON/OFF

SET_SD:ON|OFF / SET_EXT:ON|OFF / SET_OLED:ON|OFF / SET_BUZZER:ON|OFF / SET_VIB:ON|OFF

各機能をランタイムで ON/OFF し、Preferences に保存します (次回起動時も維持)。 SET_BUZZER:OFF で検出時のビープ音を、 SET_VIB:OFF で検出時の振動を消せます。デフォルトは全て ON。

状態取得は GET_SD / GET_EXT / GET_OLED / GET_BUZZER / GET_VIB。 応答は SD:ON / BUZZER:OFF / VIB:ON のような形式で返ります。

ダッシュボードの「機能スイッチ」パネルからも同じ操作ができます。

8.7 システム

GET_BLENAME / SET_BLENAME:<name>

BLE デバイス名を取得・変更します。応答は BLENAME:<name>。Preferences に保存され、再起動後に反映されます。

RESET

カウンタとデッドタイムをゼロに戻します。応答は RESET:OK。

9. BLE 接続方法

9.1 プロトコル: Nordic UART Service (NUS)

UUID用途
6E400001-B5A3-F393-E0A9-E50E24DCCA9EService
6E400002-...RX (スマホ→デバイス、Write)

9.2 接続手順

  1. スマホに汎用 BLE ターミナルアプリをインストール
    • iOS: Bluefruit Connect (Adafruit)
    • Android: Serial Bluetooth Terminal または nRF Connect
  2. アプリで "CosmicRay" を検索して接続
  3. UART / Nordic UART モードを選択
  4. イベントログが自動で流れてくる。入力欄からコマンド送信可能
送信の仕組み BLE Notify は 20 バイトごとにチャンク分割して送ります (BLE スタックの制約)。受信側では自動的に 結合されるので気にする必要はありません。

10. サーバーへのデータ送信

ダッシュボード (v2/index.html) のサイドバー「サーバーへ送信」から、測定イベントを 測定サーバー (cosmicray-server) へリアルタイム送信できます。

正本はローカル保存です サーバー送信はミラー (複製) であり、記録の正本ではありません。 通信が切れている間もデータを失わないよう、「保存フォルダを選択」による自動保存を必ず併用してください。 送信キューが上限 (50,000 件) を超えた場合、古いものから破棄されます (破棄件数は画面に表示されます)。 破棄されたイベントもメモリとローカルファイルには残っており、「未送信データを再送」で送り直せます。

10.1 ページの開き方 (重要)

ブラウザのセキュリティ制約により、ページをどの方法で開いたかによって送信できるかどうかが決まります。

ページの開き方USB / BLE 接続http:// のサーバーへ送信
file:// (ファイルを直接開く) 可 可 (ただし Chrome のバージョンによる。事前確認を推奨)
http://localhost:ポート (ローカルの簡易サーバー経由) 可 可 — 推奨
https:// (Web サイトに置いたページ) 可 不可
https:// のページからは http:// のサーバーへ送信できません ブラウザが「混在コンテンツ」として遮断するためで、サーバー側の設定では解決できません。 Web サイトからダッシュボードを配布したい場合は、サーバー側を https:// 化する必要があります。

最も確実なのは http://localhost で開く方法です。arduino/v2/ フォルダで 簡易サーバーを起動し、http://localhost:8000/index.html にアクセスしてください。 

# Python が入っていれば追加インストール不要
python -m http.server 8000

10.2 送信の開始手順

  1. サーバー URL を入力 (例: http://accel-kitchen.com:3000)
  2. 観測局 ID と パスワード を入力。この ID がサーバー上の保存先ディレクトリ名になります
  3. 必要に応じて装置ラベル (1 サイトに複数台ある場合の識別用) と緯度・経度を入力
  4. 送信レートを選択。回線が細い場合や計数率が高い場合は「10 件に 1 件」などに間引けます (間引いてもローカル保存は全件のままです)
  5. 「ログイン」 を押す。成功すると観測局ディレクトリがサーバー側に用意されます
  6. 「送信開始」 を押す。以降、受信したイベントが 1 秒ごとにまとめて送信されます

10.4 送信される項目と、送信されない項目

現行 API では一部の測定値が送信されません サーバー側の取り込み形式が CosmicWatch 用のため、湿度・気圧・Dig1〜3・Ana1〜3 は送信されません。 これらが必要な場合はローカル保存ファイル (.dat / .csv) を使用してください。 画面にも送信中は同じ注意が表示されます。

10.5 パスワードの扱い

「この PC にパスワードを保存する」は共用 PC で使わないでください チェックを入れるとブラウザ内に平文で保存されます。 さらに file:// でページを開いている場合、Chrome はすべてのローカル HTML ファイルで 保存領域を共有するため、他のローカルページからも読み取れる状態になります。

既定ではパスワードは保存されず、タブを開いている間だけメモリ上に保持されます (夜間の連続測定中に認証が切れても自動で再ログインできるようにするためです)。 測定終了後は「ログアウト」で認証情報を消去してください。

10.6 うまく送信できないとき

「サーバーに接続できません」と出る
  • ページを https:// で開いていないか確認 (10.1 の表を参照)。http://localhost で開き直すのが確実です
  • サーバー URL の綴りとポート番号 (既定 3000) を確認
  • サーバー側で CORS 設定が有効になっているか管理者に確認
ログインは通るのに送信でエラーになる
  • 観測局 ID が自分のアカウント ID と一致しているか確認。他人の ID には送信できません
  • 「拒否」件数が増える場合はサーバー側のバリデーションで弾かれています。管理者に相談してください
「未送信」件数が増え続ける
  • 回線速度に対して計数率が高すぎます。送信レートを「10 件に 1 件」以下に下げてください
  • ローカル保存は全件継続されるので、測定データそのものは失われません

11. トラブルシューティング

シリアルに何も出ない / "Booting" が表示されない
  • ボード種別が Arduino Nano ESP32 になっているか確認
  • USB CDC On Boot が Enabled か確認
  • ボーレートを 9600 に合わせる
  • BOOT + RESET で強制ブートローダに入れて再書込
OLED が真っ黒のまま
  • I²C 配線 (SDA=A4, SCL=A5) と電源 (3.3V / GND) を確認
  • OLED アドレスが 0x3C か (一部は 0x3D)
  • コード中の display.begin(SSD1306_SWITCHCAPVCC, 0x3C) を書き換え
BME280: not found とシリアルに出る
  • BME280 の I²C アドレスは 0x76 または 0x77。モジュールの SDO 端子次第
  • プルアップ抵抗が I²C バスに入っているか (通常 OLED 側に実装済み)
  • BME280 ではなく BMP280 (温度+気圧のみ) の場合は別ライブラリが必要
イベントが 1 回も記録されない
  • 閾値が高すぎる: AUTO_THRESH で再校正
  • コンパレータ出力 (D0) が来ているか、オシロで確認
  • D0 (ESP32-S3 GPIO44) の割込が動作しているか: テストで attachInterrupt 直後に triggerFlag = true を 強制セットして単発イベントが出るか確認
Dig1-3 が常に 0 (または 1)
  • 外部検出器側の出力レベル (3.3V / 5V) とスレッショルド互換性を確認
  • プルアップ/プルダウンの要否を基板回路図で確認。必要ならコード中 pinMode(DIG_IN_PINS[i], INPUT_PULLUP); または INPUT_PULLDOWN に変更
レート (Rate) が異常に高い
  • 閾値 Duty が低すぎて常時トリガーしている可能性
  • ピークホールドリセットパルス (D8) が効いていない: 配線確認
  • D0 にノイズが乗っている: グラウンド配線を見直し、PWM D2 の周波数を上げる

12. 用語集

SiPM
Silicon Photomultiplier。半導体光電子増倍管。微弱な光 (宇宙線のチェレンコフ/シンチレーション光) を検出する素子。
ピークホールド
パルス信号のピーク電圧を一時的に保持するアナログ回路。マイコンが落ち着いて ADC で読むための前段。
コインシデンス
複数の検出器で同時 (∼μs オーダー) にトリガーが出る現象。宇宙線のような貫通粒子の確度を上げるのに使う。
Duty
PWM 信号で HIGH になっている時間の比率。0-255 (8 bit) で表現。Duty × (電源電圧 / 255) ≈ 平均電圧で、コンパレータの閾値生成に使う。
デッドタイム
1 イベントの処理中は次のトリガーを取りこぼす時間帯。レート計算の際に観測時間から差し引く必要がある。
BLE / NUS
Bluetooth Low Energy / Nordic UART Service。スマホから無線でシリアル通信するためのプロファイル。
